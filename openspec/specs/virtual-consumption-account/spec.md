# virtual-consumption-account 规范

## 需求
### 需求:系统提供唯一虚拟消费账户
系统必须提供且仅提供一个系统管理的虚拟消费账户承载全部消费流水；该账户禁止由用户创建、选择、重命名、排序或删除，也禁止要求用户选择实际付款的储蓄卡。

#### 场景:直接进入消费记账
- **当** 用户打开记账页面
- **那么** 系统必须直接展示唯一虚拟消费账户的消费工作区，不显示消费卡选择器

#### 场景:消费不绑定付款储蓄卡
- **当** 用户提交一笔消费流水
- **那么** 系统必须把流水记入唯一虚拟消费账户，并禁止要求或保存实际付款储蓄卡

### 需求:当前月额度按多张储蓄卡预算求和
系统必须将月份 `m` 的消费额度计算为所有储蓄卡在 `m` 月填写的消费预算之和，并且禁止读取其他月份的消费预算作为 `m` 月额度。

#### 场景:多张储蓄卡共同提供额度
- **当** 储蓄卡 A 在 2026-08 填写 1200 元消费预算且储蓄卡 B 在 2026-08 填写 800 元消费预算
- **那么** 2026-08 的虚拟消费账户额度必须为 2000 元

#### 场景:额度严格按月隔离
- **当** 2026-07 的消费额度为 2180.95 元且 2026-08 的消费预算合计为 2000 元
- **那么** 2026-08 的额度必须显示为 2000 元，禁止显示、累加或回退到 2180.95 元

#### 场景:当月没有预算
- **当** 任意储蓄卡在目标月份都没有填写消费预算
- **那么** 目标月份额度必须为未设置或 0，禁止沿用最近月份额度

### 需求:当前月超额充值按多张储蓄卡求和
系统必须将月份 `m` 的超额充值计算为所有储蓄卡在 `m` 月填写的超额充值之和，并禁止再按多张消费卡分摊。

#### 场景:多张储蓄卡共同超额充值
- **当** 储蓄卡 A 在 2026-08 填写 100 元超额充值且储蓄卡 B 填写 50 元
- **那么** 2026-08 的虚拟消费账户超额充值必须为 150 元

#### 场景:超额充值不改变额度
- **当** 2026-08 的消费预算合计为 2000 元且超额充值合计为 150 元
- **那么** 系统必须仍将额度显示为 2000 元，并将 150 元单独用于剩余与预充计算

### 需求:月度消费指标使用统一公式
系统必须以 `本月剩余 = 本月额度 + 本月超额充值 − 本月已消费` 和 `消费超支 = max(0, 本月已消费 − 本月额度)` 计算消费指标，所有页面必须使用同一结果。

#### 场景:超额充值不抹除超预算事实
- **当** 本月额度为 2000 元、超额充值为 200 元且已消费为 2100 元
- **那么** 系统必须显示本月剩余 100 元，并同时显示消费超支 100 元

#### 场景:各页面口径一致
- **当** 用户查看同一月份的记账工作区、消费详情和统计页
- **那么** 三处展示的额度、已消费、剩余和超支必须一致

### 需求:预充暂存跨月结转但不污染额度
系统必须保留预充暂存并按月份正序结转；上月暂存只能减少本月所需的新转账并参与对账，禁止并入或替换本月额度。

#### 场景:上月预充用于本月预算
- **当** 本月期初预充暂存为 300 元且本月消费预算合计为 2000 元
- **那么** 本月使用结转必须为 300 元、本月所需新转账必须为 1700 元，而本月额度仍必须显示 2000 元

#### 场景:多张储蓄卡只使用一次结转
- **当** 多张储蓄卡共同填写本月消费预算且存在上月预充暂存
- **那么** 系统必须在全局层只计算一次结转，所有储蓄卡分配到的结转之和必须等于该全局结转

### 需求:旧消费数据安全归一化
系统必须把多张旧消费卡的消费流水归入唯一虚拟消费账户，并将旧额度数据归一化为单一月度预算来源，禁止重复计算已经迁移过的额度。

#### 场景:合并多张旧消费卡流水
- **当** 升级前存在多张消费卡及其消费流水
- **那么** 升级后必须保留每笔流水的日期、分类、金额、备注和标识，并统一归入虚拟消费账户

#### 场景:新旧额度表同时存在
- **当** 同一月份同时存在 `consumptionBudgets` 与已经被迁移过的 `spendQuotas`
- **那么** 系统必须以新预算记录为准，禁止将两套记录重复相加

#### 场景:导入旧版备份
- **当** 用户导入包含多张消费卡或旧额度表的备份
- **那么** 系统必须在写入前执行同样的归一化并得到唯一虚拟消费账户
