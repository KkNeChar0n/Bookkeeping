# summary-reporting 规范

## 目的
待定 - 由归档变更 bookkeeping-web-tool 创建。归档后请更新目的。
## 需求
### 需求:预算 vs 实际汇总
系统必须提供总结视图：储蓄卡与基金卡继续按真实卡片展示预算、实际和差额；消费侧必须作为唯一虚拟消费账户单独展示额度、已消费、剩余和超支，禁止把虚拟消费账户当作用户卡片参与真实卡片列表。

#### 场景:展示真实卡片汇总
- **当** 用户打开总结视图
- **那么** 系统必须按储蓄卡和基金卡展示适用的预算、实际与差额，并按唯一虚拟消费账户展示消费汇总

#### 场景:消费超支与剩余同时成立
- **当** 当前月已消费超过额度但尚未用完包含超额充值的可用资金
- **那么** 系统必须同时展示正的本月剩余和正的消费超支，禁止让超额充值隐藏超预算事实

### 需求:收支统计排除调账与调整
系统在任何收入/支出汇总中，必须排除 type=transfer 与 type=adjust 的记录，只统计真实收入与支出。

#### 场景:统计仅含真实收支
- **当** 系统计算某期的收入合计与支出合计
- **那么** 系统必须排除调账与调整记录，结果仅反映真实收入与支出

### 需求:年同比与月环比
系统必须提供年同比(y2y)与月环比(m2m)指标，对真实收入与支出进行跨期对比。

#### 场景:月环比对比
- **当** 用户查看某月的总结
- **那么** 系统必须展示该月真实收支与上一月的对比（环比差额或百分比）

#### 场景:年同比对比
- **当** 用户查看某月的总结
- **那么** 系统必须展示该月真实收支与去年同月的对比（同比差额或百分比）

### 需求:按筛选期间汇总唯一虚拟消费账户
系统必须在统计视图中使用唯一虚拟消费账户汇总消费额度、超额充值、已消费、剩余和超支；按月筛选时必须只使用目标自然月数据，按年筛选时必须逐月计算后再汇总。

#### 场景:按月查看消费情况
- **当** 用户选择 2026-08 按月查看统计
- **那么** 系统必须只使用 2026-08 的预算、超额充值和消费流水，禁止展示 2026-07 的额度作为 8 月额度

#### 场景:按年逐月计算超支
- **当** 用户按年查看消费超支
- **那么** 系统必须先对每个月计算 `max(0, 已消费−额度)` 再求和，禁止用全年消费与全年额度直接相减替代逐月结果

#### 场景:统计只展示一个消费汇总
- **当** 用户打开统计页的消费超支区域
- **那么** 系统必须展示唯一虚拟消费账户的一组汇总，禁止按旧消费卡拆分多行

### 需求:对账单独展示预充暂存与结转
系统必须在对账中保留预充暂存与跨月结转，并将其与当前月额度分开表达；上月暂存禁止显示为当前月消费额度。

#### 场景:当前月额度与期初暂存并存
- **当** 目标月存在 300 元期初预充且当月预算合计为 2000 元
- **那么** 统计必须把当前月额度显示为 2000 元，并在预充或结转项目中单独反映 300 元

#### 场景:多卡充值参与统一对账
- **当** 多张储蓄卡在同月填写超额充值
- **那么** 对账必须使用这些充值的月度合计，并禁止按不存在的多张消费卡分摊
