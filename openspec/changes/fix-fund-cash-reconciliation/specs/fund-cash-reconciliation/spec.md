## 新增需求

### 需求:独立预充现金与月度净投入
系统必须保存每月市值、独立预充现金和可选本月净投入。历史市值必须允许显式未知并提示总资产不完整。净投入必须为实际买入现金减赎回现金，允许负值，禁止把普通储蓄卡到预充账户的内部转账算成基金投入。预充禁止与普通储蓄余额重复计算。

#### 场景:填写买入与赎回
- **当** 用户当月买入1000元、赎回200元
- **那么** 系统必须保存本月净投入800元而非市值变化

#### 场景:预充账户调拨
- **当** 普通储蓄余额下降100元且独立预充现金增加100元
- **那么** 系统必须在净投入不变时保持实际总资产和对账残差不变

### 需求:余额沿用与流量月份隔离
系统必须仅沿用截至目标月份的最后余额，净投入必须读取目标月份精确记录。累计净投入必须只累加截至目标月的已填值，同月修改必须覆盖，禁止将未来或沿用的流量再次累加。

#### 场景:未来与缺失月份
- **当** 9月净投入100元、10月缺失、11月净投入200元，查看10月
- **那么** 10月净投入必须为未知，累计必须为100元并提示10月缺失，禁止计入11月

#### 场景:当月覆盖与赎回
- **当** 用户将10月净投入从50元改成负20元且9月为100元
- **那么** 截至10月累计必须为80元

### 需求:历史兼容与对账完整性
系统必须区分未知与确认的0，旧快照不得自动补0，必须列出首个基金快照到目标月之间未填写净投入的月份。完全没有截至目标月基金记录的账本必须保留原对账行为。用户必须可显式设置已核对的历史月底为对账起点，仅统计最后起点之后的流量和缺失月份，禁止将起点解读成当月没有投入或抹平历史残差。

#### 场景:恢复历史起点
- **当** 用户将9月设为历史起点且10月净投入100元
- **那么** 系统必须保留9月实际残差、以9月底为起点累计10月100元，禁止要求用户伪造9月净投入0

#### 场景:导入旧备份
- **当** 旧备份只含市值和预充
- **那么** 系统必须保留余额并将净投入标为未知，提示差额暂不完整

#### 场景:备份与清空非基金账本
- **当** 用户导出并重新导入包含负净投入的记录
- **那么** 系统必须完整保留负净投入；清空非基金账本时必须保留基金余额但移除旧净投入并提示重新确认
