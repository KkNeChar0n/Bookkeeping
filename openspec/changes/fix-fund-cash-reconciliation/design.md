## 上下文

用户确认预充现金独立于普通储蓄卡余额。现有实现把预充同时加入预算和实际，抵消了应被计入的现金；基金买入减少现金也没有单独表达。旧备份多次修改基金模型，历史本金与划转不能可靠推断真实投入。

## 目标 / 非目标

**目标：** 正确统计独立现金与市值，用月度净投入隔离投资现金流并保留真实利息；未知历史输入可见，月份隔离，备份兼容。

**非目标：** 不恢复多基金、逐笔划转、本金或盈亏，不按残差推算投入，不修改用户原始备份或自动更正历史金额。

## 决策

1. 快照增加可选整数分 `netInvestment`（允许负值）。缺失是未知，显式 0 是确认无净投入；沿用市值/预充余额但绝不沿用流量。累计净投入仅求截至目标月已保存的值。同月保存覆盖月总量。
2. 设储蓄预算 E、实际储蓄 S、基金预充 C、市值 M、累计净投入 N。预算基准为 E−N+M，实际为 S+C+M。保留原收入/消费拆解，利息/其他为实际−预算−收入差额+消费超支+消费预充暂存。现金内部转到预充不计 N；真正买入为正，赎回为负；市值变动中性。
3. 从首个基金快照到目标月份逐月检查净投入，缺失显示警告；完全没有截至目标月份的基金记录不警告。余额仍可沿用。表单空白保存为未知，不自动变成 0。可手动指定 `flowBaseline: 1` 为已经核对的历史月底起点，仅统计最后起点之后的净投入；它不归零残差，也不表示起点月份没有买入赎回。
4. 备份升级 v14，旧版本字段缺失保留未知，非法净投入剥离而不丢弃有效余额。清空非基金账本时保留市值/预充，移除依赖旧账本的净投入，提示需重新确认对账基准。
5. 历史市值可留空，以 `marketValueKnown: false` 显式表示未知；技术上以0代入两边，不影响残差，但必须警告历史总资产不完整。历史起点同样不得自动推断。本次账本可恢复9月预充5670并手动设为历史起点；不伪造当月净投入0。清账时同时移除所有旧起点，避免新账继续使用旧历史基准。

## 风险 / 权衡

- 历史净投入未知 → 保留缺失提示和原始残差；不能强制归零，也不依据市值变化反推投入。
- 现金重复登记 → 明示预充必须是普通储蓄卡余额之外的独立现金；已经包含的现金不重复填写。
- 历史市值缺失 → 由用户填写该月真实记录；不把9月8日市值冒充9月底市值。市值不影响残差，但影响历史总资产展示。
- 每月新增一个数字增加填报成本 → 不增加逐笔交易流程；按月填买入现金减赎回现金，0需明确填写。

## 迁移计划

类型扩展不改变索引，无需修改 Dexie 版本。旧快照保持原余额，不自动补净投入。导出保存新字段，导入兼容旧版本。代码回退不丢失既有市值与预充。
