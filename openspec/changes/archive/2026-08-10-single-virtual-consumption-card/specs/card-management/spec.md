## MODIFIED Requirements

### 需求:用户可自定义管理卡片
系统必须允许用户创建、重命名和删除储蓄卡与基金卡，并为这些真实卡片设置所需的初始金额；系统内置的虚拟消费账户禁止出现在用户卡片管理中，也禁止由用户创建、重命名或删除。

#### 场景:创建真实卡片
- **当** 用户提交一张储蓄卡或基金卡并填写名称与初始金额
- **那么** 系统必须持久化该卡片，并以初始金额作为相应余额或本金计算的起点

#### 场景:禁止创建消费卡
- **当** 用户打开设置或卡片管理页面
- **那么** 系统禁止提供“新建消费卡”入口

#### 场景:重命名真实卡片
- **当** 用户修改一张储蓄卡或基金卡的名称为新的非空名称
- **那么** 系统必须更新该名称，且不影响该卡已有的余额与流水

#### 场景:删除真实卡片
- **当** 用户删除一张储蓄卡或基金卡
- **那么** 系统必须移除该卡片；若该卡仍存在关联数据或被设为默认卡，系统必须提示并阻止删除或要求先处理关联数据

#### 场景:虚拟消费账户不可管理
- **当** 系统展示设置、卡片列表或消费工作区
- **那么** 系统禁止提供虚拟消费账户的改名、删除、初始余额或管理操作

### 需求:默认卡设置
系统必须允许用户将符合条件的真实卡片标记为默认卡，且同一时刻最多只有一张默认卡；虚拟消费账户禁止成为默认卡，消费记账也禁止依赖默认卡选择。

#### 场景:设置默认真实卡
- **当** 用户将一张符合条件的真实卡片设为默认
- **那么** 系统必须把该卡标为默认，并清除其他真实卡片的默认标记

#### 场景:消费记账不使用默认卡
- **当** 用户进入消费记账界面
- **那么** 系统必须直接使用虚拟消费账户，禁止选中或关联默认储蓄卡作为付款卡

### 需求:卡片排序
系统必须支持用户自定义储蓄卡与基金卡的展示顺序；虚拟消费账户禁止参与用户排序。

#### 场景:调整真实卡片顺序
- **当** 用户调整储蓄卡或基金卡排序
- **那么** 系统必须按新顺序持久化并在对应页面呈现，且虚拟消费账户不出现在排序列表中
