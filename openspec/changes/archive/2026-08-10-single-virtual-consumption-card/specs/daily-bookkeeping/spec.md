## ADDED Requirements

### 需求:当日消费直接记入虚拟消费账户
系统必须允许用户在消费工作区选择支出分类并录入金额、日期与备注，提交后直接将该笔支出持久化到唯一虚拟消费账户，禁止要求选择消费卡或实际付款储蓄卡。

#### 场景:记一笔当日消费
- **当** 用户选择支出分类、填写正数金额并提交
- **那么** 系统必须按所选日期持久化消费流水并刷新该日期所属月份的已消费、剩余和超支

#### 场景:消费记账无需选卡
- **当** 用户进入消费工作区
- **那么** 系统必须直接允许记账，禁止显示消费卡或付款储蓄卡选择器

#### 场景:修改消费日期后切换月度口径
- **当** 用户把一笔消费的日期从 2026-07 修改为 2026-08
- **那么** 系统必须从 2026-07 已消费中移除该金额并计入 2026-08，两个自然月分别使用各自额度

## REMOVED Requirements

### 需求:当日记账录入收入或支出
**Reason**: 原需求要求先选择一张卡并把支出下调到该卡实际余额，与已确认的全局虚拟消费流水、不关联实际付款储蓄卡的模型冲突。

**Migration**: 消费支出改由“当日消费直接记入虚拟消费账户”覆盖；既有消费卡支出迁移到唯一虚拟账户，储蓄卡收入与真实余额维护继续使用现有储蓄流程。
