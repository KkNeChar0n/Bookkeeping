## 为什么

当前系统把消费侧建模为用户可创建的多张“消费卡”，同时又把额度来源迁移到了储蓄卡的本月消费预算，导致消费卡既不像真实账户、也没有明确的选择入口；旧额度表与新预算表并存，还可能出现当前月展示历史额度、不同页面口径不一致等问题。需要将消费卡收敛为系统内唯一且不可管理的虚拟消费账户，同时保留多储蓄卡共同出资、超额充值、预充暂存和跨月结转能力。

## 变更内容

- **BREAKING** 将用户可创建、重命名、排序和删除的多张消费卡收敛为一个系统内置的虚拟消费账户；用户不再选择消费卡，记账首页直接进入全局消费流水。
- 当前月额度严格等于所有储蓄卡在当前月填写的消费预算之和，不读取或展示其他月份的消费预算。
- 当前月超额充值等于所有储蓄卡在当前月填写的超额充值之和，不再按多张消费卡比例分摊。
- 保留预充暂存与跨月结转：上月暂存只用于减少本月所需的新转账并参与对账，不得并入本月额度。
- 统一记账、详情与统计的计算口径：本月剩余 = 本月额度 + 本月超额充值 − 本月已消费；消费超支 = max(0, 本月已消费 − 本月额度)，超额充值不抹除超过预算的事实。
- 删除旧 `spendQuotas` 写入路径和多消费卡额度分配路径，建立单一额度数据源；迁移并兼容已有消费卡、消费流水和备份数据。
- 修正多张储蓄卡场景的结转展示，确保同一笔上月预充不会在多个储蓄卡页面重复抵扣。

## 功能 (Capabilities)

### 新增功能

- `virtual-consumption-account`: 定义唯一虚拟消费账户、当月额度/超额充值求和、全局消费流水、预充暂存与跨月结转的统一业务规则。

### 修改功能

- `card-management`: 用户只管理真实的储蓄卡和基金卡，不再创建、选择、重命名、排序或删除消费卡。
- `daily-bookkeeping`: 消费支出直接记入全局虚拟消费账户，不再要求选择消费卡，并按记账日期所属月份计算额度和余额。
- `summary-reporting`: 消费额度、剩余、超支、预充暂存和结转使用唯一虚拟消费账户的统一月度口径，不再按多张消费卡展示。

## 影响

- 数据模型与迁移：`cards`、`transactions`、`spendQuotas`、`consumptionBudgets`、`savingsEntries`、IndexedDB 版本升级及旧备份导入。
- 领域服务：消费预算、消费统计、对账、预充暂存、跨月结转与 React Query 缓存键。
- 界面：设置页、储蓄卡编辑页、记账首页、消费详情页和统计页。
- 测试与文档：增加跨月隔离、多储蓄卡求和、结转单次使用、旧数据迁移和各页面口径一致性测试，并同步 README 与 OpenSpec 规范。
