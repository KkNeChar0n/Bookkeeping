## 新增需求

### 需求:按月保存基金本金与市值

系统必须为每只基金按月份保存唯一的本金和市值快照；同月再次保存必须覆盖该月值，并保留其他月份。

#### 场景:更新当月市值

- **当** 用户为基金选择月份并保存市值
- **那么** 系统必须保存该月最后一次市值及当时本金，并更新基金当前展示值

#### 场景:覆盖同月快照

- **当** 用户多次更新同一基金同一月份
- **那么** 系统必须更新同一条月度快照，禁止生成重复月份

### 需求:按截止月份读取基金快照

系统必须为统计月份读取不晚于该月的最近基金快照；禁止把晚于目标月份的当前最终值用于历史统计。

#### 场景:目标月存在快照

- **当** 基金在目标月份存在快照
- **那么** 系统必须使用该月快照的本金和市值

#### 场景:目标月沿用最近快照

- **当** 目标月份没有快照但更早月份存在快照
- **那么** 系统必须沿用不晚于目标月份的最近快照

#### 场景:历史月份没有快照

- **当** 目标月份及之前均无快照
- **那么** 系统必须以基金期初本金同时作为本金和市值，并标记基金数据未填写

### 需求:基金月度快照可备份迁移

系统必须导出和导入基金月度快照；升级现有数据库或导入不含快照的旧备份时，必须以当前基金值生成一条迁移月份快照。

#### 场景:升级现有数据库

- **当** v18 数据库升级到新版本
- **那么** 系统必须为每只基金以升级月份和当前本金、市值生成快照

#### 场景:新版备份往返

- **当** 用户导出并重新导入新版备份
- **那么** 系统必须完整恢复每只基金的全部月度快照

#### 场景:导入旧版备份

- **当** 用户导入不含基金月度快照的旧备份
- **那么** 系统必须使用备份导出月份和基金当前值生成快照
