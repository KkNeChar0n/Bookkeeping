## 修改需求

### 需求:预算 vs 实际汇总

系统必须使用净资产口径提供总结视图：预算总资产必须等于储蓄预期余额加基金期初本金，实际总资产必须等于储蓄实际余额加截止月份基金市值；基金当前本金和资产划转金额禁止抬高预算总资产。消费侧必须作为唯一虚拟消费账户单独展示额度、已消费、剩余和超支，禁止把虚拟消费账户当作用户卡片参与真实卡片列表。

#### 场景:展示真实卡片汇总

- **当** 用户打开总结视图
- **那么** 系统必须按储蓄卡展示预算与实际，按统计月份展示基金本金、市值和盈亏，并按唯一虚拟消费账户展示消费汇总

#### 场景:消费超支与剩余同时成立

- **当** 当前月已消费超过额度但尚未用完包含超额充值的可用资金
- **那么** 系统必须同时展示正的本月剩余和正的消费超支，禁止让超额充值隐藏超预算事实

#### 场景:基金内部注资不改变差额

- **当** 储蓄实际余额减少一笔金额且基金本金和市值增加同额资金
- **那么** 预算总资产、实际总资产差额和其他差额必须保持不变，且禁止要求存在基金划转记录

## 新增需求

### 需求:差额拆解不依赖基金投入记录

系统必须使用 `其他差额 = 总差额 - 基金盈亏 - 收入差额 + 消费超支 + 预充暂存`，并禁止在统计中把累计基金投入作为拆解项。

#### 场景:存在或缺少基金划转记录

- **当** 相同的储蓄余额和基金月度快照分别存在完整、部分或零条基金划转记录
- **那么** 系统计算出的预算总资产、实际总资产、基金盈亏和其他差额必须完全相同

#### 场景:基金产生盈亏

- **当** 月度基金市值不同于该月本金
- **那么** 差异必须进入基金盈亏，禁止进入其他差额
