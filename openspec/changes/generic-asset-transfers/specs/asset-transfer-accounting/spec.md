## 新增需求

### 需求:记录通用资产划转
系统必须允许用户以任意储蓄卡为来源，将正数金额划转到另一张储蓄卡或一只基金，并保存日期、来源、去向、金额、备注和创建时间；来源与目标禁止相同。

#### 场景:储蓄卡划转到储蓄卡
- **当** 用户从储蓄卡 A 向储蓄卡 B 登记一笔资产划转
- **那么** 系统必须保存一条可查询的零和资金迁移记录，且禁止把它计为收入或消费

#### 场景:储蓄卡划转到基金
- **当** 用户从储蓄卡向基金登记一笔正常资产划转
- **那么** 系统必须在同一原子事务内保存划转并增加目标基金本金

#### 场景:拒绝非法目标或金额
- **当** 来源不是储蓄卡、目标类型不匹配、来源与目标相同或金额不为正数
- **那么** 系统必须拒绝提交且不写入任何数据

### 需求:历史补录不重复增加本金
系统必须为储蓄卡到基金的划转提供“本金已包含”模式；该模式必须保存完整资金解释记录，但禁止再次修改基金本金。

#### 场景:补录已包含在本金中的投资
- **当** 用户选择“本金已包含”并补录一笔储蓄卡到基金的历史划转
- **那么** 系统必须保存该记录并标记本金未由本次操作应用，基金本金保持不变

### 需求:资产划转可原子撤销
系统必须允许用户撤销资产划转。正常基金划转必须同时减回本金；历史补录和储蓄卡间划转只删除记录。任一步失败时必须整体回滚。

#### 场景:撤销正常基金划转
- **当** 用户撤销一笔已实际增加基金本金的划转
- **那么** 系统必须在同一原子事务内删除记录并从目标基金本金减去对应金额

#### 场景:撤销历史补录
- **当** 用户撤销一笔“本金已包含”的历史补录
- **那么** 系统必须只删除解释记录，禁止改变基金本金

### 需求:储蓄真实余额保持快照语义
系统禁止因新增或撤销资产划转而自动改写 `savingsActuals` 中用户填写的月度真实余额。

#### 场景:登记划转后保留月度真实余额
- **当** 用户在某月已填写储蓄卡真实余额并随后新增或撤销资产划转
- **那么** 该月真实余额必须保持用户最后填写的值

### 需求:基金本金校准可审计
系统必须为每次实际改变基金本金的人工校准保存修改前金额、修改后金额和创建时间，并禁止把本金校准到低于仍有效的已应用划转合计。

#### 场景:人工校准基金本金
- **当** 用户把基金本金从一个金额修改为另一个金额
- **那么** 系统必须更新本金并新增一条独立校准审计记录

#### 场景:本金未变化
- **当** 用户提交的基金本金与现值相同
- **那么** 系统禁止生成无变化的校准审计记录

#### 场景:校准破坏可撤销性
- **当** 用户尝试把本金改为低于尚未撤销的已应用基金划转合计
- **那么** 系统必须拒绝该校准并保持本金和审计日志不变

### 需求:资产划转备份可往返
系统必须在备份中导出和导入资产划转及本金校准审计，并继续兼容不包含这些字段的旧版备份。

#### 场景:新版备份往返
- **当** 用户导出后再导入包含资产划转和本金校准的备份
- **那么** 系统必须完整恢复两类记录及其关联关系

#### 场景:导入旧版备份
- **当** 用户导入不包含资产划转和本金校准字段的旧版备份
- **那么** 系统必须以空台账继续导入，禁止因此失败
