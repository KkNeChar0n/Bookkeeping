## 上下文

应用的储蓄余额是用户按月填写的真实余额快照，基金则在卡片上保存累计本金与当前市值。现有 `transactions` 调账只服务日常流水余额，不能解释月度储蓄快照到基金本金之间的迁移；旧版专用基金资金卡又把卡类型、批量注资和月度快照耦合在一起，已经回退。

本次在不恢复专用卡类型的前提下，引入独立的资产划转台账。月度储蓄余额是用户对现实账户的手工快照，现实转账已经包含在用户填写的结果中，因此划转台账只负责说明资金来源及去向，禁止再次扣减来源或增加接收储蓄余额；转入基金时仍增加基金本金。历史补录仍只建立解释关系，避免重复增加已经包含在现有数据中的本金。

## 目标 / 非目标

**目标：**

- 用一个通用模型记录储蓄卡到储蓄卡、储蓄卡到基金本金的划转。
- 保证新增和撤销基金划转时，划转记录与基金本金原子一致。
- 保证新增、撤销、删卡和清除月份均不会由资产划转改写月度储蓄余额快照。
- 支持“本金已包含”的历史补录，避免重复增加本金。
- 让统计可按截止月份累计基金投入，并从“利息/其他”残差中剥离。
- 所有基金本金人工校准均可审计，备份可完整往返。

**非目标：**

- 不恢复特殊基金资金卡、批量注资或基金月度市值快照。
- 不把资产划转计为收入、消费或日常收支流水。
- 不根据旧版已折叠的数据猜测具体基金分配。

## 决策

### 使用独立 `assetTransfers` 台账

每条记录保存日期、来源储蓄卡、目标类型、目标卡、金额、储蓄余额应用标记、是否已由本次操作应用到本金、备注和创建时间。储蓄余额应用标记仅用于识别并修复 v17 已经错误改写过的数据；新记录固定为 0。独立台账比复用 `transactions` 更合适，因为后者围绕日常流水派生余额，而统计使用的是 `savingsActuals` 月度余额；混用会造成同一笔钱在两个余额模型中重复生效。

考虑过复用成对 `TRANSFER` 流水，但它无法自然表达单边增加基金本金和“本金已包含”的历史补录，因此不采用。

### 划转只记录资金路径，不改月度余额快照

新增资产划转固定写入 `savingsApplied=0`，不读取或更新 `savingsActuals`，也不做来源快照余额不足校验。撤销储蓄卡间划转只删除台账；撤销基金划转只处理由该记录实际增加的基金本金并删除台账。删除卡片与清除月份同样不再反向调整或限制储蓄余额。

储蓄卡概览和详情都查询卡片作为来源或目标的划转记录，并用正负号区分转入、转出。这解决接收卡记录不可见的问题，同时保持月度快照仍由用户按真实余额填写。

v18 升级修复 v17 的重复扣减：对 `savingsApplied=1` 的每条记录，把金额加回来源卡对应月份的余额并把标记改为 0。接收卡现有余额保持不变，避免破坏用户升级后已经确认或继续使用的数据。备份 v10 对导入的 v9 数据执行同样修复；v10 记录均为 0，重复导入不会再次加回。

### 基金本金用原子事务维护

正常储蓄到基金划转在同一个 Dexie 事务内新增台账并增加 `fundPrincipal`；撤销时删除台账并减回本金。历史补录把 `savingsApplied` 与 `principalApplied` 都记为 0，因此新增和撤销均不改既有余额或本金。直接修改本金会写入 `fundPrincipalLogs`，且不得把本金调到低于仍有效的已应用划转合计。

### 对账按截止月份累计基金投入

`fundInvestment` 为日期月份不晚于统计月份的全部储蓄到基金划转金额，包含“本金已包含”的历史补录。差额拆解为：

```text
差额 = 基金盈亏 + 收入差额 + 利息/其他
     - 消费超支 - 预充暂存 - 基金投入
```

所以：

```text
利息/其他 = 差额 - 基金盈亏 - 收入差额
          + 消费超支 + 预充暂存 + 基金投入
```

储蓄卡之间的划转为总资产零和，不进入该拆解金额。

### 删除卡片时原子清理

删除卡片会清理其作为来源或目标的全部划转以及基金本金校准日志，但不修改任何仍保留储蓄卡的余额。若删除的是划转来源且目标基金仍保留，先撤销由这些记录实际增加的本金，再删除记录，避免基金本金与统计台账脱节；删除目标基金时随基金一并删除，无需额外回退。

### 备份升级为版本 10

导出包含 `assetTransfers` 和 `fundPrincipalLogs`。导入旧版本时补空数组；导入 v9 时恢复 `savingsApplied=1` 对来源月度余额造成的重复扣减并把标记归零；导入新版时做卡片存在性、卡类型和金额校验，并与其他表在同一事务中全量替换。

## 风险 / 权衡

- [用户可能期待划转自动改变月度储蓄余额] → 界面明确说明该余额是手工快照，划转用于解释资金路径，并在储蓄概览展示双方记录。
- [本金校准可能破坏之后的可撤销性] → 限制校准值不得低于仍有效、由系统实际应用的划转合计。
- [删除来源卡会改变仍保留基金的本金] → 仅回退 `principalApplied=1` 的记录，并在单一事务内完成；历史补录不会被重复扣减。
- [历史数据无法自动还原每只基金的分配] → 提供“本金已包含”补录，由用户选择目标基金，不做不可靠猜测。

## 迁移计划

1. IndexedDB v16 创建两张新表；v17 曾联动余额并写入 `savingsApplied=1`。
2. IndexedDB v18 对 v17 已应用记录加回来源月度余额、保留接收卡现值，并统一把 `savingsApplied` 归零。
3. 服务和 UI 上线后，由用户使用历史补录登记已包含在本金中的旧划转。
