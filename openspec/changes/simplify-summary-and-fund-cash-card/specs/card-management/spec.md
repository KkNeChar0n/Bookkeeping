## MODIFIED Requirements

### 需求:用户可自定义管理卡片
系统必须允许用户创建、重命名和删除普通储蓄卡，并允许在创建时显式勾选基金资金卡；基金资金卡必须仍作为储蓄卡保存并计入实际总资产，但其预算期初必须固定为0，禁止出现在预算工作区或承载预算收支。系统内置的虚拟消费账户禁止出现在用户卡片管理中，也禁止由用户创建、重命名或删除。

#### 场景:创建基金资金卡
- **当** 用户新建储蓄卡并勾选“基金资金卡”
- **那么** 系统必须以0预算期初保存该卡，在储蓄工作区提供真实余额填写，并禁止在预算工作区展示该卡

#### 场景:基金资金卡计入实际资产
- **当** 基金资金卡在目标月保存了5300元真实余额
- **那么** 实际总资产必须包含5300元，预算基准必须禁止因该卡增加

#### 场景:转换已创建的空预算卡
- **当** 一张普通储蓄卡期初为0且没有预算、收入、消费充值或消费预算记录，用户将其标记为基金资金卡
- **那么** 系统必须保留其月度真实余额并从预算工作区隐藏

#### 场景:阻止有预算记录的卡转换
- **当** 普通储蓄卡存在非零期初或预算/收入/消费资金记录
- **那么** 系统必须拒绝把它标记为基金资金卡，禁止静默删除或忽略已有金额

#### 场景:禁止基金资金卡预算写入
- **当** 用户通过直达链接或服务接口尝试给基金资金卡修改期初、添加预算收支或参与预算调拨
- **那么** 系统必须拒绝写入并保持该卡预算贡献为0

#### 场景:重命名真实卡片
- **当** 用户修改一张储蓄卡的名称为新的非空名称
- **那么** 系统必须更新该名称，且不影响该卡已有的余额与标记

#### 场景:删除真实卡片
- **当** 用户删除一张储蓄卡
- **那么** 系统必须移除该卡片及其受支持的关联数据，并重新计算统计，禁止继续引用已删除余额

#### 场景:虚拟消费账户不可管理
- **当** 系统展示设置、卡片列表或消费工作区
- **那么** 系统禁止提供虚拟消费账户的改名、删除、初始余额或管理操作
