## ADDED Requirements

### 需求:差额拆解使用简洁的月度层级
系统必须按固定顺序展示“预算余额、消费超支、收入差额、资产变动”四组。预算余额必须只展示截至所选月的汇总值；消费超支必须从最早保留的消费月份逐月展示，禁止被资产起账月截断；收入差额和资产变动必须从资产起账月逐月展示。系统禁止再单独展示“本月资产变动”，也禁止继续显示“预充暂存”“利息/其他”“新增差额”等旧名称。

#### 场景:消费历史早于资产起账
- **当** 消费超支从7月开始且资产在10月重新起账，用户查看10月或之后的统计
- **那么** 消费超支必须分别列出7月、8月、9月和10月金额，禁止把7月至9月累计值合并到10月；收入差额和资产变动必须从10月开始列出

#### 场景:展示月度差额拆解
- **当** 用户查看12月统计且资产账本从11月开始
- **那么** 系统必须在收入差额和资产变动下分别列出11月与12月金额，并使各月金额之和与对应累计总额一致

#### 场景:某月资产变动不可计算
- **当** 相邻月份存在未填写的必要储蓄余额
- **那么** 系统必须在资产变动的对应月份显示无法计算，并允许显示一条简短缺失数据告警

### 需求:统计页移除长篇口径说明
系统必须删除月份选择器下方以及差额拆解、消费、储蓄和基金区域中的长篇口径说明；系统必须保留金额、明细、状态以及会影响数据完整性的短告警。

#### 场景:查看正常月份
- **当** 目标月数据完整且没有告警
- **那么** 统计页禁止显示账本范围、公式、基金内部移动、累计口径或历史补录等说明段落

#### 场景:存在缺失数据
- **当** 储蓄余额或基金市值明确留空
- **那么** 系统必须保留对应的简短数据不完整告警
