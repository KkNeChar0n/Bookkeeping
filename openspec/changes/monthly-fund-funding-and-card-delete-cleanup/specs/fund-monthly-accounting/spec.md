## 新增需求

### 需求:基金资金卡

系统必须允许用户创建至多一张用途为“基金资金卡”的储蓄卡，并在储蓄列表中识别该用途。该卡必须按月记录月初可投资金额，并禁止当月注资总额超过可投资金额。

#### 场景:创建基金资金卡

- **当** 用户尚未创建基金资金卡并选择创建该用途的储蓄卡
- **那么** 系统必须持久化该用途并在储蓄列表中标记为基金资金卡

#### 场景:禁止重复创建

- **当** 已存在基金资金卡时用户再次创建同用途卡片
- **那么** 系统必须拒绝创建并提示只能存在一张基金资金卡

#### 场景:注资不得透支

- **当** 用户提交的当月基金注资合计大于该卡当月尚可用金额
- **那么** 系统必须拒绝整批注资且禁止产生部分记录

### 需求:可撤销的批量基金注资

系统必须允许用户从基金资金卡按月一次向一只或多只基金注资，并将同次提交保存为一个原子批次。用户必须能够撤销整批注资，撤销后所有相关基金本金与资金卡可用金额必须同时恢复。

#### 场景:向多只基金注资

- **当** 用户在目标月为多只基金分别填写正数金额并提交
- **那么** 系统必须原子保存共享批次标识的注资记录，并按各基金金额增加其派生本金

#### 场景:撤销注资批次

- **当** 用户撤销某个注资批次
- **那么** 系统必须删除该批次全部注资记录，恢复资金卡可用金额并降低对应基金派生本金

### 需求:基金本金只读派生

系统必须禁止用户直接修改基金本金。基金在目标月的本金必须等于旧数据保留的初始本金加上截至目标月的全部有效注资。

#### 场景:注资改变本金

- **当** 基金初始本金为 1000 元且截至目标月累计注资 300 元
- **那么** 系统必须显示本金 1300 元且不提供本金编辑输入框

### 需求:基金月末市值快照

系统必须按基金和月份唯一保存月末市值；修改某月市值禁止覆盖其他月份。查询历史统计时禁止使用目标月份之后的市值。

#### 场景:保存连续月份市值

- **当** 用户分别保存 2026-08 和 2026-09 的月末市值
- **那么** 系统必须保留两条独立快照，并能分别计算两个月的本金、盈亏和盈亏率

#### 场景:查看早于首条快照的月份

- **当** 用户查看的月份早于基金最早市值快照
- **那么** 系统必须显示该月市值未填，禁止使用未来快照
