## 上下文

应用当前同时存在两类“划转”：预算/日常记账中的双边 `TRANSFER` 流水，以及后来新增的 `assetTransfers` 通用资产划转台账。本次只移除后者。月度储蓄余额已经由用户填写真实快照，基金也已经按月保存本金和市值；通用资产划转不会参与净资产对账，却仍会修改基金本金、限制校准、影响删卡，并为旧版储蓄余额执行迁移修复，形成两套事实来源。

## 目标 / 非目标

**目标：**

- 让储蓄月度真实余额成为储蓄资产的唯一事实来源。
- 让带审计的基金本金校准成为基金成本基础的唯一修改入口。
- 完全移除通用资产划转的新增、查询、撤销和持久化工作流。
- 清理现有台账时保留当前余额、本金和基金月度快照。
- 导入旧备份时继续修复 v17/v9 重复扣减，但不恢复划转台账。

**非目标：**

- 不删除预算调账或日常记账中的双边 `TRANSFER` 流水。
- 不重新推算用户已经确认的历史储蓄余额或基金本金。
- 不改变净资产对账、收入、消费超支和预充结转公式。

## 决策

### 数据库 v20 删除通用资产划转表

v20 将 `assetTransfers` 的 schema 设为 `null`。升级时不撤回任何历史本金，也不修改任何储蓄余额或基金快照，因为这些值已经是用户确认后的当前事实。相比保留隐藏表，直接删除可以避免后续删卡、校准或统计再次意外读取旧记录。

### 基金本金只通过校准维护

删除基金划转自动加减本金以及“不得低于有效划转合计”的约束。本金校准继续原子写入基金卡、所选月份快照和审计日志；市值更新保持不变。这样申购、赎回只需校准一次本金，不再选择来源卡或维护撤销关系。

### 旧备份先兼容修复再丢弃台账

备份提升为 v12，新导出不再包含 `assetTransfers`。输入类型继续接受旧字段：对于 `savingsApplied=1` 的旧记录，规范化阶段先把曾被旧版本重复扣减的来源月度余额加回，再丢弃全部通用资产划转。基金本金使用备份中已经保存的最终值，禁止根据记录再次加减。

### UI 与服务完整移除

删除资产划转服务、React Query hooks、储蓄页新增表单、储蓄详情和基金详情中的划转列表/撤销按钮。卡片删除事务不再扫描或回退划转；只清理被删除卡自身的数据。本次不触碰交易流水服务中的 `TRANSFER`，避免误删预算调账和日常双边转账。

## 风险 / 权衡

- [用户失去资金路径备注] → 以简化和单一事实来源为优先；必要说明可写在余额或本金校准相关备注之外，但本次不新增另一套台账。
- [只更新基金市值会把新增投入误认为盈利] → 基金发生申购或赎回时必须校准本金；页面文案明确这一点。
- [旧备份含重复扣减修复标记] → 导入时仍执行一次修复并以测试覆盖，然后丢弃记录。
- [回退旧版本后缺少 `assetTransfers` 表] → 发布前建议导出 v12 备份；旧版本不作为数据结构回滚目标。

## 迁移计划

1. 发布 v20 数据库，删除 `assetTransfers` 表并保留所有余额、本金和快照。
2. 发布 v12 备份格式；旧备份先修复 `savingsApplied=1` 再忽略划转台账。
3. 移除服务、hooks 和所有用户入口，简化本金校准与删卡事务。
4. 使用现有 v9 用户备份验证邮政银行恢复为 `102125.85`、基金卡保持 `3245.00`，且导入后无资产划转记录。
