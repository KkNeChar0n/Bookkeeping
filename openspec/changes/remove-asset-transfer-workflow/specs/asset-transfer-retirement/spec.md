## 新增需求

### 需求:移除通用资产划转工作流

系统禁止提供储蓄卡到储蓄卡或储蓄卡到基金的独立通用资产划转新增、查询和撤销能力，且禁止持久化新的通用资产划转台账；预算调账和日常记账中的双边 `TRANSFER` 流水必须继续可用。

#### 场景:储蓄页面不再提供资产划转

- **当** 用户打开储蓄列表、储蓄卡详情或基金详情
- **那么** 系统禁止展示通用资产划转表单、记录列表或撤销按钮

#### 场景:保留记账双边转账

- **当** 用户在预算或日常记账中记录两张卡之间的 `TRANSFER`
- **那么** 系统必须继续按既有双边零和规则处理，禁止因本次变更移除该能力

### 需求:升级时清理划转台账但保留资产事实

系统升级现有数据库时必须删除全部通用资产划转记录，且禁止因此修改任何储蓄月度余额、基金本金、基金市值或基金月度快照。

#### 场景:清理已应用的基金划转

- **当** 数据库包含一笔曾增加基金本金的通用资产划转并升级到新版本
- **那么** 系统必须删除该记录，同时保持基金当前本金和全部月度快照不变

#### 场景:清理储蓄卡间划转

- **当** 数据库包含储蓄卡之间的通用资产划转并升级到新版本
- **那么** 系统必须删除该记录，同时保持来源卡和目标卡的月度真实余额不变

### 需求:旧备份兼容后丢弃划转台账

系统必须接受包含旧通用资产划转字段的备份；若旧记录标记了来源余额曾被重复扣减，系统必须先恢复来源余额，再丢弃全部通用资产划转。新版备份禁止继续导出该台账。

#### 场景:导入带重复扣减标记的旧备份

- **当** 用户导入包含 `savingsApplied=1` 通用资产划转的旧备份
- **那么** 系统必须把金额加回来源卡对应月份，保持目标卡余额和基金本金不变，并禁止恢复该划转记录

#### 场景:新版备份往返

- **当** 用户导出并重新导入新版备份
- **那么** 备份中禁止包含通用资产划转台账，且储蓄余额、基金本金和基金快照必须完整保持
