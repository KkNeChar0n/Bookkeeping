## 修改需求

### 需求:预算 vs 实际汇总

系统必须提供总结视图：储蓄卡与基金卡继续按真实卡片展示预算、实际和差额；基金卡必须使用卡片当前保存的本金与市值展示盈亏，禁止按筛选月份切换基金金额；消费侧必须作为唯一虚拟消费账户单独展示额度、已消费、剩余和超支，禁止把虚拟消费账户当作用户卡片参与真实卡片列表。

#### 场景:展示真实卡片汇总

- **当** 用户打开总结视图
- **那么** 系统必须按储蓄卡展示适用的预算与实际，按基金卡展示当前本金、市值和盈亏，并按唯一虚拟消费账户展示消费汇总

#### 场景:基金统计不随月份变化

- **当** 用户在不同月份或年度之间切换统计筛选
- **那么** 系统必须继续使用基金卡当前本金和市值，禁止展示基金月度快照或月度仓位

#### 场景:消费超支与剩余同时成立

- **当** 当前月已消费超过额度但尚未用完包含超额充值的可用资金
- **那么** 系统必须同时展示正的本月剩余和正的消费超支，禁止让超额充值隐藏超预算事实

### 需求:按筛选期间汇总唯一虚拟消费账户

系统必须在统计视图中使用唯一虚拟消费账户汇总消费额度、超额充值、已消费、剩余和超支；按月筛选时必须只使用目标自然月数据，按年筛选时必须逐月计算后再汇总。汇总下必须保留可展开的逐月明细，每月展示额度、已消费和超支。

#### 场景:按月查看消费情况

- **当** 用户选择 2026-08 按月查看统计
- **那么** 系统必须只使用 2026-08 的预算、超额充值和消费流水，并在月度明细中展示 2026-08，禁止展示 2026-07 的额度作为 8 月额度

#### 场景:按年逐月计算超支

- **当** 用户按年查看消费超支
- **那么** 系统必须先对每个月计算 `max(0, 已消费−额度)` 再求和，并允许展开核对每个月的额度、已消费和超支，禁止用全年消费与全年额度直接相减替代逐月结果

#### 场景:统计只展示一个消费汇总

- **当** 用户打开统计页的消费超支区域
- **那么** 系统必须展示唯一虚拟消费账户的一组汇总，禁止按旧消费卡拆分多行
