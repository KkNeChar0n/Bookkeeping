## 修改需求

### 需求:预算 vs 实际汇总
系统必须以储蓄池口径提供总结视图：预算总资产必须等于储蓄预期余额加截至统计月份的基金当前市值与预充金额，实际总资产必须等于储蓄实际余额加同一组基金当前市值与预充金额；基金金额禁止改变实际与预算的差额。消费侧必须作为唯一虚拟消费账户单独展示额度、已消费、剩余和超支，禁止把基金池或虚拟消费账户当作用户卡片参与真实卡片列表。

#### 场景:展示储蓄池汇总
- **当** 用户打开总结视图
- **那么** 系统必须展示储蓄卡的预算与实际、基金储蓄池的当前市值与预充金额，以及唯一虚拟消费账户的消费汇总

#### 场景:基金金额对差额中性
- **当** 用户只修改某月基金当前市值或预充金额
- **那么** 预算总资产与实际总资产必须增加相同金额，总差额和利息/其他必须保持不变

#### 场景:消费超支与剩余同时成立
- **当** 当前月已消费超过额度但尚未用完包含超额充值的可用资金
- **那么** 系统必须同时展示正的本月剩余和正的消费超支，禁止让超额充值隐藏超预算事实

## 新增需求

### 需求:基金不再参与盈亏拆解
系统必须禁止计算或展示基金本金、盈亏和收益率，差额拆解只能基于收入差额、消费超支、预充暂存与利息/其他。

#### 场景:统计历史月份
- **当** 用户查看任意包含基金储蓄池记录的月份
- **那么** 系统必须按截至该月的当前市值与预充金额展示基金资产，并且禁止出现基金盈亏项
