## 上下文

当前实现把基金建模为多张 `FUND` 卡，每张卡保存本金和市值，另有本金审计和按月本金/市值快照。统计再用本金、市值和盈亏拆解总差额。这套模型与用户现在只关心“基金当前市值”和“尚未投入的预充金额”的使用方式不匹配。

## 目标 / 非目标

**目标：**

- 基金页退化为一个全局、按月保存的储蓄资产池，仅包含当前市值和预充金额。
- 两项金额计入总资产，但同时进入预算侧和实际侧，从而不改变对账差额。
- 删除多基金、本金、盈亏、详情和本金审计的用户心智与实现。
- 无损保留旧基金市值；避免把旧本金错误当成新增资产。
- 新旧备份均可导入。

**非目标：**

- 不跟踪单只基金、申购赎回、收益率、成本或资金来源。
- 不自动把名称包含“基金”的普通储蓄卡折叠进基金池。
- 不根据基金金额反推或修改任何储蓄卡真实余额。

## 决策

1. 新增 `fundSavingsSnapshots` 表，以 `month` 为唯一键保存 `marketValue` 和 `prepaid`。使用独立全局表而不是隐藏基金卡，可以彻底移除基金卡排序、详情、删除和默认卡等无关能力。
2. 数据库升级聚合旧数据：对旧快照涉及的每个月，按“截至该月每只基金最后一条快照”汇总市值；若没有旧快照，则为当前月汇总卡片最终市值。预充统一置 0，因为旧本金是已经投入的成本，映射为预充会与市值重复计算。
3. 升级完成后删除旧 `FUND` 卡、基金本金审计和基金月度快照，并清理这些卡的关联记录。普通 `SAVINGS` 卡（包括用户命名的基金卡）保持原样。
4. 基金页按月份读取最近一条不晚于目标月份的记录用于展示；保存时为目标月份写入完整的两个数。历史统计同样使用截至目标月的最近值。
5. 对账公式使用 `基金储蓄池 = 当前市值 + 预充金额`，并把它等额加到预算总资产和实际总资产。删除 `fundProfit` 和 `fundsFilled`，因此基金修改对 `diff` 与 `interest` 均为中性。
6. 备份格式升级，导出新表；导入旧格式时执行与数据库升级相同的聚合规则。新备份不再导出基金卡、本金日志或旧基金快照。

## 风险 / 权衡

- [旧本金不会出现在新模型] → 这是有意行为；本金是成本信息，不是独立资产，保留会造成双计。
- [旧基金卡的名称与逐只历史不可恢复] → 备份兼容层先聚合市值；升级前的原始备份仍可用于追溯，但新 UI 不再暴露明细。
- [基金金额同时进入预算和实际看似重复] → 两者是同一对账基准的两侧，不会在单侧总资产内重复；这样既展示总资产，又满足基金不影响差额的目标。
- [历史月份没有精确快照] → 延续“截至目标月最后已知值”规则，并在完全没有历史值时按 0 处理。

## 迁移计划

1. IndexedDB 升级到 v21，先聚合旧基金市值写入新表。
2. 清理旧基金卡及关联数据，删除旧基金表。
3. 备份规范升级并保留旧版本归一化入口。
4. 通过迁移、备份、服务、对账和 UI 回归测试验证。

回滚只能通过用户升级前的备份恢复到旧应用版本；新格式不会伪造已删除的逐只基金与本金信息。
