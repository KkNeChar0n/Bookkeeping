## 上下文

当前基金快照同时保存市值、独立预充现金和月度净投入；手工重新起账还固定开账基金市值与现金。对账通过“储蓄预期－累计净投入＋当前市值”让买入和市值涨跌都保持中性。用户现在使用现实中的专用银行卡保存基金待投资现金，预充与普通储蓄余额成为重复模型，并且净投入漏填会直接产生假差额。

现有手工期初已经包含起账时的银行现金、基金现金和基金市值，因此可以把该总额直接视为一次性的总资产预算起点。以后预算只随正常收入与支出滚动，实际资产则按每月所有储蓄余额和基金当前市值重算。

## 目标 / 非目标

**目标：**

- 基金只保存按月当前市值，基金待投资现金由普通储蓄卡承载。
- 总资产预算只使用已经包含基金的既有期初与正常预算收支，不再进行基金开账、市值或净投入校准。
- 内部银行卡转账和资金卡买基金不作为预算支出；基金市值涨跌进入资产变动/其他。
- 旧备份可以继续导入，旧字段不参与新计算，迁移过程不自动写入或删除真实账本。

**非目标：**

- 不计算或拆分基金盈亏、持仓、本金、买卖流水。
- 不从余额变化推断哪张银行卡是基金资金卡。
- 不自动创建卡片、修改卡片期初或复制旧预充，避免重复资产。

## 决策

1. 基金活跃模型仅保留 `month`、`marketValue`、未知市值标记和更新时间。数据库与备份读取继续容忍旧 `prepaid`、`netInvestment`、`flowBaseline` 字段，服务和统计忽略它们；用户再次保存该月市值时用新形状覆盖旧快照。
2. 对账预算基准直接等于所有储蓄卡的预算预期合计。手工期初以前已按总资产填写，禁止再加入当前基金或开账基金。实际总资产等于所有储蓄卡实际余额加目标月基金市值，差额仍为实际减预算。
3. 删除基金首次确认、缺失净投入月份和历史流量起点的完整性门禁。基金没有快照视为0；明确留空市值仍提示总资产不完整，但不阻塞其它账目读取。
4. “利息/其他”更名为“资产变动/其他”。现有收入差额、消费超支和消费充值对账拆解保留；剩余项自然包含基金市值变化、银行利息和其它未解释资产变化。
5. 用户把基金现金迁移为普通储蓄卡时，新卡预算期初必须为0，或者从原卡期初等额调出以保持期初合计不变。历史各月真实余额由用户依据备份填写；旧预充在新公式中不计入，防止与新卡重复。

## 风险 / 权衡

- 基金涨跌进入剩余差额，无法与银行利息自动分离 → 名称改为资产变动/其他，并在统计中明确说明。
- 升级后尚未创建资金卡时，实际总资产会暂时少旧预充 → 基金页展示旧预充迁移提示和金额，指导先备份再按月填卡，不自动搬运。
- 旧备份仍含废弃字段 → 导入严格校验其安全整数和范围，但新计算忽略，重新保存市值后自然清理该月旧字段。
- 新卡加入后旧月份若无余额会导致储蓄完整性提示 → 迁移说明列出需要补填的历史月份及金额。

## 迁移计划

1. 发布前用最新备份在隔离 IndexedDB 中验证新旧公式和迁移前后总资产。
2. 部署代码；不执行数据库金额迁移，不改变当前卡片或预算期初。
3. 用户先导出备份，新建普通储蓄卡“基金资金卡”，预算期初填0；按旧快照把各月预充填写为该卡真实余额。
4. 用户核对所有储蓄卡与基金市值处于同一时点。旧预充和净投入不再参与计算，无需补预算基金支出。
5. 回滚代码时旧字段仍在备份/数据库中；回滚前应重新导入变更前备份，避免新模型期间缺少旧净投入。

## 待决问题

无。用户已选择基金市值涨跌进入资产变动/其他，以换取只维护储蓄余额和基金市值的简单模型。
