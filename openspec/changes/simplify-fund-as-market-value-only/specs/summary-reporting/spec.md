## MODIFIED Requirements

### 需求:预算 vs 实际汇总
系统必须提供总结视图：总资产预算基准必须等于所有储蓄卡预算预期合计，既有手工期初作为一次性总资产起点且不得再逐月加入基金；实际总资产必须等于所有储蓄卡实际余额加目标月基金当前市值。差额必须为实际总资产减预算基准。消费侧必须作为唯一虚拟消费账户单独展示额度、已消费、剩余和超支，禁止把虚拟消费账户当作用户卡片参与真实卡片列表。

#### 场景:基金资金内部移动保持总资产中性
- **当** 普通储蓄卡减少3000元、基金资金储蓄卡先增加后买入3000元而月底余额不变、基金市值增加3000元
- **那么** 实际总资产必须保持不变，预算基准禁止生成基金支出或基金校准金额

#### 场景:基金市值涨跌进入总差额
- **当** 所有储蓄余额及正常收支均不变而基金市值增加500元
- **那么** 实际总资产和总差额必须增加500元，预算基准必须保持不变

#### 场景:展示真实卡片汇总
- **当** 用户打开总结视图
- **那么** 系统必须按普通储蓄卡展示保存金额，并按唯一虚拟消费账户展示消费汇总；基金区域只能展示目标月当前市值

#### 场景:消费超支与剩余同时成立
- **当** 当前月已消费超过额度但尚未用完包含超额充值的可用资金
- **那么** 系统必须同时展示正的本月剩余和正的消费超支，禁止让超额充值隐藏超预算事实

## ADDED Requirements

### 需求:剩余差额表示资产变动与其他
系统必须将原“利息/其他”展示名称改为“资产变动/其他”，并明确该值可以包含基金市值涨跌、银行利息、历史补录及其它未解释变化。系统禁止把该值宣称为基金盈亏或真实利息。

#### 场景:基金上涨进入剩余项
- **当** 基金市值上涨500元且没有其它差异
- **那么** 资产变动/其他必须为正500元，并说明这不是单独计算出的基金盈亏
