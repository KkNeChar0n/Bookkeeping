## MODIFIED Requirements

### 需求:用户可自定义管理卡片
系统必须允许用户创建、重命名和删除储蓄卡，并为这些真实卡片设置所需的初始金额；基金待投资现金必须使用普通储蓄卡管理，系统禁止创建独立基金卡或基金现金账户。系统内置的虚拟消费账户禁止出现在用户卡片管理中，也禁止由用户创建、重命名或删除。

#### 场景:创建基金资金储蓄卡
- **当** 用户创建名为“基金资金卡”的储蓄卡
- **那么** 系统必须把它作为普通储蓄卡持久化并计入储蓄实际余额，禁止同时生成基金预充账户

#### 场景:迁移时保持期初合计
- **当** 既有手工期初已经包含原基金预充，用户新建基金资金储蓄卡
- **那么** 系统必须提示新卡预算期初填0或从原卡等额调出，禁止让卡片期初合计增加

#### 场景:禁止创建消费卡和基金卡
- **当** 用户打开设置或卡片管理页面
- **那么** 系统禁止提供“新建消费卡”或“新建基金卡”入口

#### 场景:重命名真实卡片
- **当** 用户修改一张储蓄卡的名称为新的非空名称
- **那么** 系统必须更新该名称，且不影响该卡已有的余额与流水

#### 场景:删除真实卡片
- **当** 用户删除一张储蓄卡
- **那么** 系统必须移除该卡片及其受支持的关联数据，并重新计算统计，禁止继续引用已删除余额

#### 场景:虚拟消费账户不可管理
- **当** 系统展示设置、卡片列表或消费工作区
- **那么** 系统禁止提供虚拟消费账户的改名、删除、初始余额或管理操作
