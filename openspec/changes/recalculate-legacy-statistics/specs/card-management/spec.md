## 修改需求

### 需求:用户可自定义管理卡片

系统必须允许用户创建、重命名和删除储蓄卡与基金卡，并为这些真实卡片设置所需的初始金额；储蓄卡可被标记为普通用途或唯一的基金资金卡。系统内置的虚拟消费账户禁止出现在用户卡片管理中，也禁止由用户创建、重命名或删除。删除非默认真实卡片时，系统必须在用户确认后原子删除卡片及其全部关联数据，使后续统计不再包含已删除卡片的数据。应用升级或导入旧备份时，系统必须清理旧版本已经遗留的孤立卡片关联记录，使所有历史月份从有效原始数据重新计算。

#### 场景:创建真实卡片

- **当** 用户提交一张储蓄卡或基金卡并填写名称与初始金额
- **那么** 系统必须持久化该卡片，并以初始金额作为相应余额或本金计算的起点

#### 场景:禁止创建消费卡

- **当** 用户打开设置或卡片管理页面
- **那么** 系统禁止提供“新建消费卡”入口

#### 场景:重命名真实卡片

- **当** 用户修改一张储蓄卡或基金卡的名称为新的非空名称
- **那么** 系统必须更新该名称，且不影响该卡已有的余额与流水

#### 场景:删除真实卡片及关联数据

- **当** 用户确认删除一张非默认储蓄卡或基金卡
- **那么** 系统必须在单个事务中删除该卡及预算、储蓄、消费预算、基金和流水关联记录，并使统计立即排除这些数据

#### 场景:删除含成对调账的卡片

- **当** 被删除卡片参与了实际或预算层成对调账
- **那么** 系统必须同时删除调账两端，禁止为其他卡片留下单边记录

#### 场景:升级后修正历史统计

- **当** 用户数据库中存在旧版本删卡遗留的孤立收支、预算、储蓄、消费预算或基金记录并升级应用
- **那么** 系统必须在单个升级事务中清除确定属于已删除卡片的记录，并让全部历史月份只按仍存在的卡片重新计算

#### 场景:旧备份不得恢复孤立数据

- **当** 用户导入包含已删除卡片孤立记录的旧备份
- **那么** 系统必须保留有效卡片及系统虚拟消费账户的合法历史记录，并禁止写入孤立记录或残缺的成对调账

#### 场景:默认卡禁止直接删除

- **当** 用户尝试删除默认卡
- **那么** 系统必须拒绝删除并提示先设置其他默认卡

#### 场景:虚拟消费账户不可管理

- **当** 系统展示设置、卡片列表或消费工作区
- **那么** 系统禁止提供虚拟消费账户的改名、删除、初始余额或管理操作
