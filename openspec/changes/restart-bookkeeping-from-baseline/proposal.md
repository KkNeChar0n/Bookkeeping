## 为什么

历史预算与余额经过人工调平，无法可靠追溯。用户需要从当前核实的资产重新记账，同时保留每月消费查询，避免旧消费和基金现金继续污染新账对账。

## 变更内容

- 旧资产预算、余额、收入与基金记录删除；保留消费、各月消费定额和超额充值、卡片与分类。起账前下载文件备份，但应用不再保存旧账归档。
- 期初与当前资产由用户在原页面自行填写；总预算期初 = 当前银行余额 + 截至起账月累计消费定额 + 累计超额充值 + 基金市值 + 独立基金现金。累计定额在起账月预算记一次支出，基金不得再次全额叠加。
- 消费资金与超支持续按历史累计，资产独立从新起点对账。旧月消费可以统计，但不伪造已清除的旧资产对账。
- 已清掉消费定额与充值的账本，可从清账前备份只预览并补回消费资金，不覆盖现有消费资金或恢复旧资产。
- 首次保存基金确认已含在人工期初的固定基金基准，后续买入、市值变化与现金内部流动不造成假差额。
- 起账信息、固定基金基准和消费标记随备份导入导出，兼容没有新字段的旧备份和早期归档模式备份。
- 删除旧“清空普通账本（保留基金）”入口及其清空服务，只保留备份导入导出和消费保留式重新起账，避免误删消费。

## 功能 (Capabilities)

### 新增功能

- `bookkeeping-restart`: 仅保留消费的事务式清账、手工开账和文件备份恢复。

### 修改功能

- `virtual-consumption-account`: 消费定额、充值、已花、超支和真实结转完整保留；资产重新起账不截断消费历史。
- `summary-reporting`: 对账和超支明确新账范围，起账月不比较旧账残差。

## 影响

涉及 Dexie 起账元数据、兼容备份、事务式清账服务、消费/基金/对账服务、设置入口与范围提示及隔离测试。早期归档表仅用于备份兼容，不再新增旧账归档。不新增依赖，不推送或自动修改实际账本。
