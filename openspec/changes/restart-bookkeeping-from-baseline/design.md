## 上下文

现有预算、真实余额、收入、充值和基金净投入按月保存，覆盖式编辑没有日级流水。单纯按月份截断会重复计入起账当月已经发生的收支；只过滤对账也会使消费页与统计不一致。工作区已有“本月新增差额”展示，必须保留。

## 目标 / 非目标

**目标：** 旧资产账目删除，只保留消费、卡片和分类，用户手工重填新预算及储蓄；本月消费完整参与本月额度，旧月完整保留查询；期初包含基金时不重复计算；不修改真实设备数据，只有用户点击确认才执行。

**非目标：** 不推算历史真实余额，不恢复基金明细/盈亏，不实现任意过去日期的半月收入拆分，不自动调平之后的残差。

## 决策

### 用户澄清后的最终决策

1. 起账只清账，不亲填或自动生成资产余额。先单独下载完整文件备份，用户确认文件已保存后才允许执行清账。再事务清空预算、储蓄余额/收入/充值/日志、消费定额、基金及旧归档，所有卡片期初清零；保留卡片、分类与 OUT 消费，消费统一到虚拟账户并解除转账关联。不会实际操作用户账本，用户确认按钮才执行。
2. `manualOpening: true` 区分手工含基金期初；`startDate` 为本月1日，是月度消费范围而非假定该日资产余额。当前月和未来消费仍参与额度；更早月份仅查询。旧模式备份保留原口径，不自动转换。
3. 用户自行填各卡预算期初，总和为银行实际 + 本月定额 + 超额充值 + 基金总额；当月只记一笔正常定额预算支出。已发生收入不再重填。储蓄页填写当月定额/超额充值和当前真实银行余额。初月不使用旧结转；之后沿用既有结转口径。
4. 首次保存起账月基金时明确确认已纳入人工期初的市值与现金（无基金也确认0），净投入必须为0。事务同时保存固定期初基金值和 `fundOpeningConfirmed: true`，之后基金净投入仅记录此确认后的买入减赎回；首月以后不能替代缺失的开账确认。手工模式对账预算 = 银行预算预期 − 起账基金市值 + 当前基金市值 − 新账累计净投入，不额外加基金现金。实际仍为银行实际 + 当前市值 + 当前基金现金。基金涨跌等额进两侧，内部流动不产生假差额。
5. 起账月按人工重建基准计算新增差额，不能声称用户尚未填写时资产已核实或自动调平；基金未确认时不提供完整新增差额。备份保留手工模式标记和固定基金基准，严格验证非法标记。
6. 不保留新的本地旧账归档；清空已有归档。旧归档表仅为已有备份兼容而保留，不再提供起账归档入口。撤销清账只能导入下载的备份（会覆盖新账）。

## 风险 / 权衡

- 删除旧资产记录不可原地撤销 → 先下载备份；事务失败整体回滚；导入文件恢复会覆盖新账，必须先备份新账。
- 期初包含基金 → 单卡预算不能再等同银行卡预期；手工模式隐藏逐卡差额，使用总资产对账。
- 首次基金净投入容易误填全月历史买入 → 首次必须填0，明确此前资金变化已在当前资产与手工期初内；随后仅记录新买入。
- 定额不自动扣预算 → 明确指引在预算中记一次定额支出，不能再次扣超额金额；本月定额/充值补填，之前收入不能重记。
- 清旧预算也清未来计划 → 确认中明确提示，未来计划需重新填写。

## 迁移与回滚

Dexie v23 起账表及兼容归档表不自动迁移金额或起账。未使用功能的账本行为不变。导入起账前下载文件可恢复当时账本，但会覆盖后续新账，沿用既有导入确认。早期归档模式备份继续使用其原有公式；新手工模式备份包含 `manualOpening` 与 `fundOpeningConfirmed` 并严格验证。
