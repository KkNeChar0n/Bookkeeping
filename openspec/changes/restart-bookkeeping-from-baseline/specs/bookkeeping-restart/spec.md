## ADDED Requirements

### 需求:确认当前资产后事务式重新起账
系统必须提供手工重新起账入口，确认后在同一事务中删除全部非消费账目及旧本地归档，卡片期初清零，保留卡片、分类和消费。禁止自动起账或自动填写新资产。必须先提供独立的完整文件备份下载步骤，用户确认文件已保存后才能执行清账。

#### 场景:起账成功
- **当** 用户明确确认仅保留消费后重新起账
- **那么** 旧预算、储蓄、基金及日志必须清空，不能留下完整本地归档；用户之后自行填写新的期初和资产，本月消费继续计入本月额度

#### 场景:无效输入或写入失败
- **当** 事务中任一步失败
- **那么** 系统必须拒绝操作或完整回滚，禁止只清空部分旧账

### 需求:独立基金现金进入起账基准
手工期初已包含基金市值和独立基金现金，系统禁止再次全额叠加基金。首次确认起账月基金必须固定市值和现金基准且净投入为0，后续净投入从此确认后累计；基金基准未确认不得报告完整新增差额。

#### 场景:基金现金开账
- **当** 银行余额100元、定额20元、充值5元、基金现金10元、市值50元，手工期初185元并记定额支出20元
- **那么** 预算基准必须为165元、实际160元，差额为-5元，利息其他为0，基金不得重复叠加

#### 场景:起账同月买入和利息
- **当** 起账后同月用10元基金现金买入并记录净投入10元，银行另产生1元利息
- **那么** 基金买入不得产生未解释差额，利息其他必须增加1元

### 需求:手工起账数据可恢复
系统必须完整导出和导入起账配置、手工模式、固定基金基准及消费历史标记，兼容无起账字段的旧备份及早期本地归档备份。清账不新增本地归档；清空账本必须同时清除起账元数据。

#### 场景:新备份往返
- **当** 起账后导出再导入
- **那么** 手工期初、固定基金基准与消费范围必须保持不变，不得重新激活旧月份消费

#### 场景:导入旧备份
- **当** 导入没有新字段的旧备份
- **那么** 系统必须恢复原有计算方式，不得沿用当前设备之前的起账基准
