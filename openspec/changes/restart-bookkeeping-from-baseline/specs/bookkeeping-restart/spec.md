## ADDED Requirements

### 需求:确认当前资产后事务式重新起账
系统必须提供手工重新起账入口，确认后在同一事务中删除旧资产预算、余额、收入、基金、日志及本地归档，卡片期初清零。保留卡片、分类、全部消费及截至起账月的各月消费定额和超额充值；未来资金计划必须清除。禁止自动起账或自动填写新资产。必须先提供独立的完整文件备份下载步骤，用户确认文件已保存后才能执行清账。

#### 场景:起账成功
- **当** 用户明确确认仅保留消费后重新起账
- **那么** 旧资产账必须清空，不能留下完整本地归档；用户之后自行填写新的期初和资产，全部消费、历史定额与超额充值持续累计

#### 场景:无效输入或写入失败
- **当** 事务中任一步失败
- **那么** 系统必须拒绝操作或完整回滚，禁止只清空部分旧账

### 需求:独立基金现金进入起账基准
手工期初已包含基金市值和独立基金现金，系统禁止再次全额叠加基金。首次确认起账月基金必须固定市值和现金基准且净投入为0，后续净投入从此确认后累计；基金基准未确认不得报告完整新增差额。

#### 场景:基金现金开账
- **当** 银行余额100元、定额20元、充值5元、基金现金10元、市值50元，手工期初185元并记定额支出20元
- **那么** 预算基准必须为165元、实际160元，差额为-5元，利息其他为0，基金不得重复叠加

#### 场景:起账同月买入和利息
- **当** 起账后同月用10元基金现金买入并记录净投入10元，银行另产生1元利息
- **那么** 基金买入不得产生未解释差额，利息其他必须增加1元

### 需求:手工起账数据可恢复
系统必须完整导出和导入起账配置、手工模式、固定基金基准及累计消费模式标记，兼容无起账字段的旧备份及早期本地归档备份。消费累计标记只能用于手工起账；旧无标记备份保持原口径。清账不新增本地归档；清空账本必须同时清除起账元数据。

#### 场景:新备份往返
- **当** 起账后导出再导入
- **那么** 手工期初、固定基金基准与消费范围必须保持不变，累计消费模式下的历史定额与充值不得丢失

#### 场景:导入旧备份
- **当** 导入没有新字段的旧备份
- **那么** 系统必须恢复原有计算方式，不得沿用当前设备之前的起账基准

### 需求:只保留消费保留式起账入口
系统必须删除旧“清空普通账本（保留基金）”界面与服务方法，禁止以隐藏入口继续提供此旧清空功能。备份导入导出和消费保留式重新起账必须继续可用；移除功能不得自动执行任何账本删除。

#### 场景:查看设置
- **当** 用户打开设置
- **那么** 仅有“重新起账 · 只保留消费”的清账入口及备份导入导出，不出现旧清空按钮、危险操作说明或旧清空确认流程

### 需求:只恢复缺失的历史消费资金
系统必须提供清账前备份的只读消费资金预览，用户明确确认后只补缺失的各卡各月消费定额和超额充值，并启用累计消费模式。禁止覆盖现有定额或充值，禁止导入旧消费流水、卡、资产预算、余额、收入或基金。必须忽略起账月之后的计划，拒绝损坏金额或无法匹配的卡，并在写入失败时回滚。重复执行不得重复加钱。

#### 场景:清账后定向恢复
- **当** 手工账选择有历史定额及充值的清账前备份并确认
- **那么** 仅缺失消费资金被补入，现有新账资产和消费流水保持不变，历史消费重新参与累计

#### 场景:预览后新增金额或重复恢复
- **当** 用户在预览后已填某卡某月定额或充值，或再次导入同一份文件
- **那么** 必须以当前已填值为准，不能覆盖或重复追加
