# 记账（本地 PWA）

预收预算 + 当日记账 + 对账总结。纯前端、无后端，数据只存在设备本地（IndexedDB）。
可作为 PWA「添加到主屏幕」在手机上离线使用。

## 功能

- **卡片** — 用户管理普通储蓄卡；基金待投资现金也使用普通储蓄卡（如“基金资金卡”）。消费使用唯一的系统虚拟账户，不对应实际付款储蓄卡，也无需选择、命名或排序。
- **当日记账** — 直接记录全局消费流水，可选择日期、分类、金额和备注，并可回改或删除。
- **预算 vs 实际** — 预算层按日期滚动计算，与实际层逐卡对比，超支标红；预算内可在储蓄卡间「调出/调入」（零和成对，删一条自动级联删除对手卡上配对的另一条）。
- **虚拟消费账户** — 当月额度 = 所有储蓄卡在该月填写的消费预算之和；本月剩余 = 当月额度 + 当月超额充值 − 当月已消费；超支 = max(已消费 − 当月额度, 0)，超额充值不会掩盖超支，也不会读取上个月额度。
- **统计** — 「消费·分类统计」每个分类可点击展开，列出该分类下每一笔明细（日期、备注、金额）。
- **储蓄卡** — 单卡录入真实储蓄额 / 本月收入 / 超额充值（覆盖式，非累加）及该卡对全局消费预算的贡献；多张卡贡献相加，预充结转只在全局计算一次后按贡献比例分配。
- **基金** — 只按月填写当前总市值，不计算本金、投入或盈亏；未填写新月份时沿用最近一次市值，明确留空表示市值未知。
- **对账/统计** — 预算基准 = 所有储蓄卡预算预期合计；实际总资产 = 所有储蓄卡真实余额 + 基金当前市值。差额拆解为收入差额 + 资产变动/其他 − 消费超支 − 消费充值对账余额；“资产变动/其他”可能包含基金市值涨跌、银行利息、历史补录及其它未解释变化。
- **重新起账** — 设置中仅保留“重新起账 · 只保留消费”清账入口。先下载并确认备份已保存，再删除旧资产预算、储蓄余额、收入、基金及日志；保留消费、卡片、分类，以及截至起账月各月的消费定额和超额充值，随后手填新资产账。消费持续按完整历史累计，不会自动清账。

### 重新起账怎么填写

- 先核实同一时点的所有储蓄卡余额和基金市值。基金待投资现金放在一张普通储蓄卡中；银行余额填写真实当前值，不再扣一次保留的历史消费。
- 各卡预算期初合计 = 当前所有储蓄卡余额 + 截至起账月累计消费定额 + 累计超额充值 + 基金当前市值。它是一次性的总资产起点；基金市值只在这里加入一次，以后不随基金变化调整预算期初。统计页的“完整消费累计”可核对定额与充值。
- 在起账月预算只记一次截至起账月的“累计消费定额”支出；不要再补旧月份资产流水，也不要将超额充值再记成预算支出。以后各月正常填写当月完整定额及其预算支出。已包含在当前余额中的旧收入不要补记。
- 消费明细、各月定额、超额充值、逐月超支及消费资金结转继续按完整历史计算；旧月份仍可查看消费超支，但已删除的旧预算和资产不能对账。资产差额中的结转只统计起账月之后的月份，起账月及此前资金已包含在新期初，不重复扣减当前真实余额。
- 若已使用此前版本清账，升级不会自动推算或恢复消失的资金，也不会自动切换计算口径。请先在“设置 → 恢复历史消费资金”选择清账前备份，只读核对各月定额、超额充值及待补组数；下载并确认当前新账备份保存成功后，明确确认恢复。仅补缺失的卡片月份资金，不覆盖已填资金，忽略起账月之后的资金计划，不导入消费流水或旧预算、余额、收入、基金、日志；确认后才启用完整历史累计。随后按累计口径检查新预算期初和那一笔定额支出。不要使用全量备份导入覆盖新账来恢复消费资金。

### 基金怎么填写

- 在“设置”中新建普通储蓄卡“基金资金卡”，现实中该卡有多少待投资现金，就在储蓄页按月填多少真实余额。
- 基金页只填目标月已持有基金的当前总市值。历史市值查不到可留空；没有当月记录时沿用最近一次市值。
- 普通储蓄卡转到基金资金卡是内部转账；用基金资金卡买基金时，资金卡余额减少、基金市值增加。两种操作都不记基金预算支出，也不再填写净投入。
- 基金市值涨跌只改变实际总资产，不改变预算基准，因此会进入统计的“资产变动/其他”；该项不是系统单独算出的基金盈亏。
- 从旧版迁移时，基金页会列出旧预充余额。按月把它们填入普通基金资金卡；如果既有预算期初已经包含这笔现金，新卡期初填 0，不能增加全局预算期初合计。重新保存对应月份市值后，该月旧预充/净投入字段会被清理。

## 技术

- `apps/web` — React + Vite + TS，移动优先，Dexie 本地存储，vite-plugin-pwa（`autoUpdate`）。
- 领域逻辑（余额引擎 / 预算滚动 / 覆盖周期 / 超支 / 消费预充结转 / 统计）为纯函数，含单元测试。
- 行为规格见 `openspec/specs/`（account-transfer、budget-planning、budget-actual-comparison、card-management、daily-bookkeeping、summary-reporting、sync-backend）。

## 本地开发

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 领域纯函数单测
npm run typecheck
npm run build      # 产物在 apps/web/dist
```

## 数据

- 全部数据存本机 IndexedDB，无账号、打开即用。
- 「卡片」页 → 数据备份 → **导出/导入** JSON。这是唯一的备份与换机迁移方式，请定期导出。

## 部署到 GitHub Pages（免费 HTTPS）

已内置 `.github/workflows/deploy.yml`，推送到 `main` 即自动构建并发布。

1. 在 GitHub 新建仓库（例如 `bookkeeping`）。
2. 本地推送：
   ```bash
   git init && git add -A && git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/<用户名>/bookkeeping.git
   git push -u origin main
   ```
3. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
4. 等 Actions 跑完，访问 `https://<用户名>.github.io/bookkeeping/`。

> 构建时用仓库名作为子路径（`BASE_PATH=/<repo>/`），由 Actions 自动注入；路由用 HashRouter，子路径下刷新不会 404。

## 装到 iPhone

用 Safari 打开上面的 Pages 网址 → 分享 → **添加到主屏幕**。之后有独立图标、全屏、离线可用，数据只在手机里。
